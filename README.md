# ✈️ 국내 여행지 추천 CLI 프로그램

여행 날짜를 입력하면 **Google Gemini**가 그 시기에 어울리는 국내 여행지와 하루 일정을 추천하고, **카카오 로컬 API**로 해당 지역의 맛집을 조회해 **마크다운 여행 리포트**를 자동으로 만들어 주는 Python CLI 프로그램입니다.

```text
날짜 입력 ─▶ [1] Gemini 추천 (도시·날씨·행사·일정) ─▶ [2] 카카오 맛집 검색 ─▶ [3] 리포트 저장
```

---

## 1. 주요 기능

| 기능 | 설명 |
|---|---|
| AI 여행지 추천 | 입력한 날짜 무렵에 좋은 국내 도시 1곳, 날씨, 행사, 추천 이유, 하루 일정(오전/점심/오후/저녁) |
| 맛집 검색 | 추천 도시의 음식점 5곳 (이름, 주소, 카테고리, 카카오맵 링크) |
| 리포트 생성 | 마크다운 리포트(`.md`)와 원본 데이터(`.json`) 저장 |
| 결과 요약 출력 | 터미널에서 바로 핵심 결과 확인 |
| 안전한 오류 처리 | 원인별 안내 메시지, 필요한 경우에만 자동 재시도 |

## 2. 프로젝트 구조

```text
my_travel_app/
├── .env                 # API 키 보관 (Git 제외 필수)
├── .gitignore           # .env, results/ 등 제외 설정
├── main.py              # 메인 실행 프로그램
├── README.md            # 프로그램 설명서
└── results/             # 실행 결과 자동 저장 폴더
    ├── result_YYYYMMDD_HHMMSS.json   # 원본 데이터 (AI 추천 + 맛집 + 오류 기록)
    └── report_YYYYMMDD_HHMMSS.md     # 최종 마크다운 여행 리포트
```

## 3. 개발 및 실행 환경

- Python 3.10 이상
- 의존성 패키지: `google-genai`, `python-dotenv`, `requests`
  (Pydantic은 `google-genai`와 함께 설치됩니다.)

```bash
pip install google-genai python-dotenv requests
```

## 4. API 키 설정 (.env)

프로젝트 최상위 폴더에 `.env` 파일을 만들고 키를 작성합니다. **따옴표 없이** 적는 것이 가장 안전합니다.

```env
GEMINI_API_KEY=your_gemini_api_key_here
KAKAO_REST_API_KEY=your_kakao_rest_api_key_here

# 선택: 사용할 Gemini 모델명 (생략하면 코드의 기본값 사용)
GEMINI_MODEL=사용할_모델명
```

- 카카오 키는 **REST API 키**를 사용해야 합니다. (JavaScript 키 등을 넣으면 401 오류)
- 사용 가능한 모델명은 `client.models.list()`로 확인할 수 있습니다.

`.gitignore` 예시:

```gitignore
.env
results/
__pycache__/
```

> ⚠️ **보안 주의**: `.env`에는 실제 API 키가 들어 있으므로 Git 저장소에 커밋하거나 타인에게 공유하지 마세요. 반드시 `.gitignore`에 등록합니다.

## 5. 실행 방법

터미널(CMD, PowerShell 등)에서 실행합니다.

```bash
python main.py --date 2026-10-15    # 날짜 지정
python main.py -d 2026-10-15        # 짧은 옵션
python main.py                      # 날짜를 물어봄 (엔터 = 오늘)
```

- 날짜 형식은 `YYYY-MM-DD`입니다. 형식이 틀리면 안내 메시지를 출력합니다.
- 긴 옵션은 하이픈 **두 개**(`--date`)입니다. 하이픈 하나짜리 `-date`는 `-d ate`로 해석되어 오류가 납니다. (아래 문제 해결 참고)

### 실행 화면 예시

```text

[1/3] AI 가 여행지를 고르는 중...

[2/3] 경주 맛집을 검색하는 중...
```

## 6. 결과물 확인

실행이 끝나면 `results/` 폴더에 실행 시각 기준으로 파일 2개가 생성됩니다.

1. `result_YYYYMMDD_HHMMSS.json`: AI 추천 결과, 맛집 검색 결과, 오류 기록(`errors`)을 담은 원본 데이터
2. `report_YYYYMMDD_HHMMSS.md`: 추천 이유, 날씨, 행사, 맛집, 하루 일정이 정리된 마크다운 리포트

> 날씨와 행사는 AI가 생성한 **일반적인 정보**입니다. 실시간 예보가 아니므로 방문 전에 꼭 확인하세요.

## 7. 동작 방식

1. **AI 추천 (Gemini 1회 호출)**: 추천 도시, 날씨, 행사, 이유, 하루 일정을 한 번에 요청합니다. 응답 구조는 Pydantic 스키마(`response_schema`)로 고정합니다.
2. **맛집 검색 (카카오 로컬 API)**: `"{도시} 맛집"`을 음식점 카테고리(`FD6`)로 제한해 5곳을 조회합니다.
3. **리포트 생성 (로컬)**: AI를 다시 호출하지 않고 파이썬이 직접 마크다운을 만듭니다. 호출 횟수와 할당량 사용이 줄고 출력 형식이 항상 같습니다.

### 오류 처리 정책

| 상황 | 동작 |
|---|---|
| 429 / 500 / 503 (한도 초과, 서버 혼잡) | 서버 권장 대기시간 또는 6초, 12초 순으로 최대 3회 재시도 (카운트다운 표시) |
| 서버 권장 대기시간이 90초 초과 | 일일 할당량 소진으로 보고 재시도 없이 안내 |
| 400 / 401 / 403 (키 오류) | 재시도 없이 "API 키 확인" 안내 후 종료 |
| 404 (모델명 오류) | 재시도 없이 `GEMINI_MODEL` 확인 안내 후 종료 |
| AI 응답 형식 오류 | 대기 없이 즉시 종료하고 재실행 안내 |
| 카카오 API 실패 / 키 없음 | 맛집 섹션을 "데이터 없음"으로 처리하고 리포트는 정상 생성, 오류는 JSON의 `errors`에 기록 |

AI 추천이 실패했을 때 임의의 도시(예: 서울)로 대체하지 않고 종료합니다. 사용자가 잘못된 추천을 받는 일을 막기 위해서입니다.

## 8. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `argument -d/--date: ... 'ate'` | `-date`(하이픈 1개)를 `-d` + `ate`로 해석한 것입니다. `--date` 또는 `-d`를 사용하세요. |
| `GEMINI_API_KEY 가 .env 파일에 없습니다` | `.env` 위치(프로젝트 최상위), 변수 이름, 오타를 확인하세요. `main.py`와 같은 폴더에서 실행해야 합니다. |
| 오류 코드 404 | 모델명이 올바르지 않습니다. `GEMINI_MODEL`을 확인하세요. |
| 오류 코드 429 | 사용 한도 초과입니다. 잠시 후 또는 내일 다시 시도하세요. |
| 맛집이 "데이터 없음" | 카카오 키가 REST API 키인지 확인하고, `errors` 항목(JSON)을 확인하세요. |
| 한글이 깨져 보임 (Windows) | 터미널 인코딩 문제일 수 있습니다. `chcp 65001` 실행 후 다시 시도하세요. |

## 9. 학습 포인트

### ① REST API와 HTTP 메서드 (GET / POST)
- **GET**: 서버의 데이터를 조회할 때 사용하며, 요청 값이 URL 쿼리에 들어갑니다. (예: 카카오 로컬 검색으로 맛집 조회)
- **POST**: 서버에 데이터를 보내 처리를 요청할 때 사용하며, 요청 값이 본문(Body)에 들어갑니다. (예: Gemini에 프롬프트를 보내 응답 생성)

### ② LLM 출력의 구조화 (JSON 스키마)
- AI 응답을 자유 텍스트가 아닌 JSON으로 받으면 `recommended_city` 같은 값을 정확히 꺼내 다음 단계(맛집 검색)의 입력으로 넘길 수 있습니다.
- 프롬프트로 "JSON으로 답해 달라"고 부탁하는 것보다, `response_schema`로 구조를 강제하는 편이 파싱 오류가 훨씬 적습니다.

### ③ 외부 API 오류 처리 원칙
- 오류의 **종류에 따라** 대응을 다르게 합니다. 일시적 오류(429/503)는 재시도하고, 영구적 오류(키·모델명 문제)는 즉시 원인을 알려 줍니다.
- 부가 기능(맛집)이 실패해도 핵심 결과(추천 리포트)는 제공합니다. 반대로 핵심 기능(AI 추천)이 실패했는데 성공한 것처럼 보이게 하지는 않습니다.

### ④ 역할 분리
- 판단과 창작이 필요한 부분(추천, 일정)만 AI에 맡기고, 정해진 형식의 문서 생성은 코드로 처리합니다. 비용이 줄고 결과가 안정적입니다.

### ⑤ 환경변수(.env)로 비밀 정보 관리
- API 키를 소스코드에 넣지 않고 `.env`로 분리하면 코드가 유출되어도 키는 지킬 수 있고, 무단 과금 같은 사고를 막을 수 있습니다.

### ⑥ 사용자 경험(UX)
- 진행 단계 표시(`[1/3]`), 대기 카운트다운, 결과 요약 출력, 원인별 해결 안내처럼 CLI 프로그램도 사용자가 "지금 무슨 일이 일어나는지" 알 수 있게 만드는 것이 중요합니다.
